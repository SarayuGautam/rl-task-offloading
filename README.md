# Q-Learning for Task Offloading in 3-Tier Device-Edge-Cloud Systems

**EGPG 600, Problem Assessment Project.** Sarayu Gautam, Department of Computer Science and Engineering,
Kathmandu University.

A tabular Q-learning agent decides where each incoming task runs: **locally** on the device, on a
nearby **edge** server, or in the distant **cloud**. The objective is a composite cost of
0.7 × latency + 0.3 × device energy. The agent is trained and evaluated in a SimPy discrete-event
simulator with Poisson arrivals, a Shannon-Hartley uplink and a single-server edge queue.

## Results

All numbers come from `results/summary.json` and are regenerated by the command under *Reproduce*.
Every agent is evaluated greedily with its Q-table **frozen**. Evaluation uses channel quality 0.9,
five seeds, and workloads disjoint from training.

| Comparison (5 seeds) | Q-learning cost change | 95% CI | paired t(4), p |
|---|---|---|---|
| vs Always-Cloud (best fixed baseline) | **−15.60 %** (cheaper) | [13.47 %, 17.74 %] | 20.31, 3.5 × 10⁻⁵ |
| vs Always-Edge (proposal baseline) | −19.84 % (cheaper) | [16.68 %, 22.99 %] | 15.71, 9.6 × 10⁻⁵ |
| vs Greedy Heuristic (untrained, sees task CPU demand) | **+6.32 %** (more expensive) | [3.57 %, 9.08 %] | −6.38, 3.1 × 10⁻³ |

- The learned policy never executes locally. It uses the edge when the edge is idle and the cloud when
  the edge is busy.
- The latency-energy Pareto frontier is **degenerate**: offload energy does not depend on the destination.
- Simulator checks: the queueing primitive matches M/M/1 theory within 0.39 %. The full simulator
  matches M/G/1 (Pollaczek-Khinchine) and closed-form cloud/local latencies within 0.21 %.
- One-at-a-time α/γ/ε-decay sensitivity (5 seeds each) is in `results/summary.json` → `sensitivity`
  and in Table 4.4 of the report.

## Reproduce

```bash
python -m pip install -r requirements-dev.txt      # pinned versions (Python 3.11)
python -m pytest -q tests                           # unit tests: tiny-MDP Q*, freezing, closed-form simulator checks
python repro/reproduce_all.py                       # every table/figure/number (~30 min on 2 cores, resumable)
python report/build_v2.py                           # rebuild report/EGPG600_Report_SarayuGautam_v2.docx from results/
```

`repro/reproduce_all.py` writes checkpoints to `results/raw/`, the summary to `results/summary.json`,
simulator checks to `results/validation.json`, and figures (PNG + vector PDF) to `results/figures/`.
Single stages can be run on their own, for example `python repro/reproduce_all.py main finalize figures`.

The original CLI still works: `python main.py --agent {qlearning,all,stats,validate,pareto,local,edge,cloud,random,heuristic}`.
